# paytesla.kr 콘텐츠 품질 감사와 대표 글 30편 편집 계획

- 감사일: 2026-08-28
- 거절 화면: Google AdSense `가치가 별로 없는 콘텐츠`
- 대상: `lib/guides.js`의 기존 정적 가이드 57편
- 결과: 대표 글 30편 공개, 중복·경험담·시점 의존 글 27편은 대표 글로 301 통합

## 판단

기존 파일에는 글이 57편 있었지만 `STATIC_GUIDES_ARCHIVED=true`, `GUIDES_SECTION_PUBLIC=false` 상태여서 목록·홈·사이트맵·정적 생성에서 모두 빠져 있었다. 콘텐츠 수는 저장소 기준으로만 많았고 실제 공개 정적 가이드는 0편이었다.

원문은 대체로 4~6개 섹션과 출처 필드를 갖고 있었으나 다음 문제가 섞여 있었다.

- 같은 검색 의도를 날짜·지역·표현만 바꿔 여러 글로 나눈 경우
- `완벽 가이드`, `완전 정리`, `솔직한 판단`처럼 정보보다 포장을 앞세운 제목
- 공식 문서명이 없는 기관 홈페이지 수준의 출처
- 가격·보조금·FSD처럼 변동성이 큰 주제를 특정 시점의 결론으로 고정
- 실제 검증 근거 없이 1인칭 사용 경험을 주장한 글
- 글끼리 연결 기준이 없어 카테고리 순환만 하던 관련 글

따라서 글 수를 더하는 대신 구매자가 결정을 내리는 순서에 따라 대표 질문을 정하고, 나머지 URL을 대표 글로 합쳤다. 원문은 Git 이력과 파일에 남겨 복구할 수 있게 했다.

## 편집 기준

Google 공식 문서의 사람 중심 콘텐츠 자기점검 항목을 다음 코드 규칙으로 바꿨다.

- 한 글은 하나의 구체적인 구매 질문에 답한다.
- 대상 독자, 확인 시점, 결정에 미치는 영향을 상단에 표시한다.
- 첫 섹션에서 답을 먼저 제시하고 근거와 제한을 이어서 설명한다.
- 조건을 비교하는 표와 계약 전 실행 체크리스트를 포함한다.
- 가격·정책·요금은 기준일과 공식 출처를 표시하며 최신 공식 문서를 우선한다.
- 관련 대표 글 3편과 짧은 구매 질문 페이지를 연결해 다음 행동으로 이어지게 한다.
- 과장형 제목, 이모티콘, SEO 키워드 반복, 검증되지 않은 1인칭 경험을 사용하지 않는다.
- 글자 수 자체를 목표로 삼지 않되 얕은 자동 글을 막기 위한 최소 구조 검사는 적용한다.

참고한 공식 기준:

- Google Search Central, 사람 중심의 유용하고 신뢰할 수 있는 콘텐츠: https://developers.google.com/search/docs/fundamentals/creating-helpful-content
- Google Search Central, 생성형 AI 콘텐츠 지침: https://developers.google.com/search/docs/fundamentals/using-gen-ai-content
- Google Search 스팸 정책, 대규모 콘텐츠 악용: https://developers.google.com/search/docs/essentials/spam-policies
- Google AdSense 승인 문제, 고유하고 풍부한 콘텐츠: https://support.google.com/adsense/answer/81904

## 내부 순환 구조

각 대표 글은 같은 문구의 글을 무작위로 추천하지 않는다.

1. 글 상단에서 대상 독자와 확인 시점을 제시한다.
2. 본문 중간에서 해당 조건을 직접 계산할 수 있는 계산기로 이동한다.
3. 글 하단에서 다음 구매 단계의 대표 글 3편으로 이동한다.
4. 더 좁은 질문은 `/answers/[slug]`로 연결한다.
5. 답변 페이지와 계산기는 다시 관련 모델·비용·충전 페이지로 연결된다.

이 구조는 사용자가 같은 정보를 반복해서 읽는 대신 `정보 확인 → 계산 → 비교 → 계약 점검` 순서로 이동하도록 설계했다.

## 자동화 운영 원칙

- 정기 실행: 매월 1편, 한 실행에서 1편을 넘지 않음
- 주제 선정: 최근 GSC 검색어, 기존 제목, 최근 카테고리, 공식자료 검색 결과를 함께 확인
- 자료 범위: 제조사·정부·공공기관 1차 출처만 허용
- 품질 기준: 본문 2,200자 이상, 섹션 5개 이상, 설명 문단 10개 이상, 판단표 1개, 체크리스트 5개, 공식 출처 2개, 관련 글 3개
- 자동 보류: 과장 표현, 이모티콘, 가상 1인칭 경험, 비공식 출처, 중복 주제, 구조 미달
- 재작성: 최대 2회. 세 번째 검사에서도 미달이면 파일을 수정하지 않고 작업 실패
- 반영: `npm run content:audit`, 단위 테스트, 프로덕션 빌드가 모두 통과한 경우에만 GitHub Actions가 정적 파일을 커밋·푸시

자동화의 목적은 정해진 주기로 글을 채우는 것이 아니다. 실제 검색 질문이 기존 대표 글에서 충분히 해결되지 않을 때만 독립 정적 페이지를 추가하고, 품질 기준을 충족하지 못하면 아무것도 발행하지 않는 것이다.
